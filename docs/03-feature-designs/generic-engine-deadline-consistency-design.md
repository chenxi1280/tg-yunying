# 通用引擎截止边界一致性（本地验证）

## Intake / Product Handoff

- intake_id: generic-engine-deadline-consistency-20260910
- 用户授权：修复通用引擎，用中性测试数据验证；不部署。
- 分级：L2；阶段：product → dev → qa；验收仅限本地，不包含生产恢复。
- 所有新测试使用虚构租户、账号和任务；不读取生产配置，不运行远端业务调用，不修改线上任务。

## Root Cause Grouping 与设计合同

1. 来源准入必须遵守原始截止时间的开区间：实际调用时间与预约时间都必须早于 deadline。超期候选不能推进来源游标，不能持有 reserved 占位。记录既有 pacing_source_period_exhausted；不缩短原间隔、不延长 deadline、不改任务数量。
2. 生成准备的截止时间耗尽属于明确的领域异常；保留 ValueError 兼容性，其他校验错误必须继续暴露。评论 worker 对确定未执行的过期生成做终态结算，不能 finally 重置成 pending；Provider 或 Gateway 未决状态不能借过期结算清除。
3. 终态结算必须保留原业务身份和真实欠量。评论自己的义务与通用投影、动作及预约在同一事务收口；已确认或未知义务不能被重开或伪造成功。
4. 本次不改变任务领取优先级、来源平均间隔算法、账号时间窗、活群专用来源游标、历史预约恢复算法。浏览/点赞/评论均验证通用截止边界；活群验证已有专用路径及未知调用防重。

## Product Design Complete 自检

- 需求/接口：不新增外部 API，不变更 payload 输入合同；结果继续使用既有过期错误码。
- 数据：无需 schema 迁移。所有更新依赖原事务和原行锁，失败整体回滚；不批量清理历史数据。
- 并发：保留已有 owner/token 与来源行锁；异常结算必须核对持有的生成领取。
- 前端：复用已有失败/跳过展示，禁止展示为成功。
- 权限：不引入线上恢复入口，不改租户边界。
- 边界：截止前、恰好截止、截止后；同一预约重入；先有合法未来预约；已有未知/成功事实；未知异常；活群回归。
- QA：先确认中性反例失败，再实现并运行定向测试；每次后端测试进程硬超时 60 秒。
- 发布：用户明确不部署，本轮不进入 Release Gate，不合并到 master/release，不推送。

设计状态：complete（限定上述本地截止一致性范围）。提升吞吐、填补历史执行缺口及线上恢复不在本设计验收范围。
