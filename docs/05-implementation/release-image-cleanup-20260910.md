# 部署完成后清理前一次镜像文件

- 用户要求：每次部署完成后都清理前一次镜像文件；本次实现自动流程，不立即清理当前生产。
- Product：本地发布 PRD 增加成功后清理合同，运行手册、AGENTS 和索引同步。保留当前和任何容器使用的镜像、清单/日志，明确旧镜像删除后回滚需重新提供制品。
- 实现：原服务器发布锁内 capture 当前三个准确引用/ID（包含旧 GHCR 来源）；完整安装/健康/Provider/调度和版本读回后清理旧未使用镜像及可校验旧包、本次服务器传输包。取消 docker load 后过早删除包。所有失败安装均保留本次包。
- 本地：只有独立运行读回成功后才清理同目标/evidence 父目录的前次成功制品；文件锁/开始时间避免旧完成回调覆盖新指针。本次包、尚未部署候选及其他项目保持；不全局 prune、不 force。清理失败与 runtime 成功分别记录。
- QA：8 个相关文件 72 项通过（8.43 秒），另增加清理失败保留 runtime 成功回执回归；每轮 pytest 外层硬超时 60 秒。Shell/AST/Python3.6 主机兼容及函数长度检查通过。
- 真实 Docker：创建两个本次独立 scratch 测试镜像和一个 Created 状态测试容器，验证旧镜像被容器引用时保留；删除该测试容器后精确旧镜像删除成功，新镜像保持。所有本次测试对象已按精确 ID/引用清理，既有应用镜像未动。
- 状态：本地验证通过；这不能证明生产已安装该代码或已执行自动清理。旧镜像实际清理在后续新版本发布成功时发生。
